Async Cheat Sheet

Callback: function passed to another function and called later. 
setTimeout(() => console.log("done"), 1000);

But the real problem is not the callback itself — it is nested callbacks.

step1(() => {
  step2(() => {
    step3(() => {
      console.log("Done");
    });
  });
});

That shape is hard to read and hard to debug. This is callback hell.

readUser((err, user) => {
  if (err) return callback(err);

  readOrders(user.id, (err, orders) => {
    if (err) return callback(err);

    readDetails(orders[0], (err, details) => {
      if (err) return callback(err);

      callback(null, { user, orders, details });
    });
  });
});

Callbacks also use the error-first convention: callback(err, data)

function readFile(callback) {
  const error = null;
  const data = "file content";
  callback(error, data);
}

readFile((err, data) => {
  if (err) {
    console.log("Error:", err);
    return;
  }
  console.log(data);
});

Interview answer: callback is the oldest async pattern, but nesting makes code difficult to read.

new Promise: creates async work with resolve/reject. 
new Promise((resolve, reject) => {
  resolve("OK");
});

Interview answer: Promise gives a cleaner way to represent a future value and its success/failure.

async: makes a function return a Promise. 
async function demo() {
  return "Hello";
}

Interview answer: async tells JavaScript that this function is asynchronous and returns a Promise.

await: waits for a Promise inside async function. 
async function demo() {
  const x = await Promise.resolve("Hi");
  console.log(x);
}

Interview answer: await pauses execution until the Promise settles, making async code look synchronous.

Promise.all: waits for all promises; one failure fails all. 
Promise.all([p1, p2, p3]);

Interview answer: use Promise.all when all tasks must complete; if one rejects, the whole operation rejects.

Promise.allSettled: waits for every promise and returns every result, including failures. 
const results = await Promise.allSettled([p1, p2, p3]);

results.forEach((result) => {
  if (result.status === "fulfilled") {
    console.log("Success:", result.value);
  } else {
    console.log("Failure:", result.reason);
  }
});

Interview answer: use Promise.allSettled when every task matters and you need both successful values and failure reasons.

Promise.race: first promise to settle wins. 
Promise.race([p1, p2]);

Interview answer: use Promise.race for timeout or first-response-wins logic; it settles on the first result or failure.

try/catch + await: handles async errors cleanly. 
async function test() {
  try {
    await Promise.reject("Error");
  } catch (e) {
    console.log(e);
  }
}

Interview answer: try/catch makes async failure handling feel like normal JavaScript error handling.

Scenarios:
  • Callback: event listeners, timers, old APIs, file operations.
  • new Promise: wrap custom async logic such as a network request or database read.
  • async/await: fetch API data, login flow, sequential steps in one readable function.
  • Promise.all: load 3 independent API calls together: user, orders, profile.
  • Promise.allSettled: collect every API result even when one or more requests fail.
  • Promise.race: timeout handling or first response wins from multiple servers.
  • try/catch + await: handle 404, 500, or failed login in a clean way.
  • Playwright: await page.click(), await page.fill(), await expect(locator).toBeVisible().
